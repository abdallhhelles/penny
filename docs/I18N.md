# Penny — languages and translation guide

Penny ships with **English** (source), **Spanish** and **Arabic** (right-to-left). Both Spanish and Arabic are *drafts*
(`"status": "draft"` in their files) and should be reviewed by a native speaker before you call them final.
Adding another language needs **no code change** — you add one JSON file.

## How it works (one page)

| Piece | File | Job |
|---|---|---|
| Messages | `renderer/locales/<code>.json` | All interface text. One file per language. |
| Translation engine | `renderer/i18n.js` | Looks up a key, fills `{variables}`, picks plural forms, falls back to English. No money or dates in here. |
| Display formatting | `renderer/fmt.js` | Numbers, currency, percentages, dates, times for a regional locale (`Intl`). **Display only.** |
| Runtime | `renderer/lang.js` | Loads the language at start, applies `<html lang dir>`, switches language live, persists the choice. |
| Financial logic | `renderer/core.js` | Calculations always use plain numbers and ISO dates (`2026-10-14`). They never see translated text. |

**Language never changes your data.** Amounts are stored as plain numbers, dates as `YYYY-MM-DD`, and category/account names exactly as typed.
Switching language only changes how the same values are *shown*. This is covered by an automated test (transactions and accounts are byte-identical on disk before/after switching to Arabic).

The chosen language is saved in `system.json` (next to the data file), not in your financial data, so it is available on the very first screen and is not touched by export, import or restore.

Fallback order for any text: **selected language → its base language (`es-MX` → `es`) → English → the key itself** (the last case is logged as `i18n: missing key …`).

## Adding a language

1. Copy `renderer/locales/en.json` to `renderer/locales/<code>.json` (`fr.json`, `pt-BR.json`, `de.json` …).
2. Edit the `meta` block:
   ```json
   "meta": { "name": "French", "nativeName": "Français", "dir": "ltr", "region": "fr-FR", "status": "draft" }
   ```
   * `dir`: `ltr` or `rtl` (Arabic, Hebrew, Persian, Urdu … use `rtl`).
   * `region`: the default number/date format for this language (any code in the "Number & date format" list works; users can still pick another).
3. Translate the **values** in `strings`. Never change a key. You may leave keys out — missing ones show English.
4. Run `npm run i18n:check`. It fails on: placeholders that differ from English, HTML in a string, bad JSON, bad `meta`. It reports how complete the language is (`--strict` makes any gap an error).
5. Start Penny → **Settings → Language & money → Language**. The language appears automatically (marked ★ if it was loaded from the user folder, see below).

**Without rebuilding the app:** put the file in `%APPDATA%\Penny\locales\<code>.json`. Penny loads it at start and it overrides a bundled file with the same code. Files over 2 MB are ignored.

### Rules for translators

* **Variables** `{name}`, `{amount}`, `{count}` must be kept exactly (you may move them). They are filled by Penny, already formatted for the user's locale.
* **Plurals** use suffixes on the key: `_zero`, `_one`, `_two`, `_few`, `_many`, `_other`. Provide the forms your language uses
  (English: `one`, `other`. Arabic: all six. Spanish/French: `one`, `other`, and `many` for large numbers if needed). `_other` is the required catch-all. An explicit `_zero` is used for the number 0 in every language.
  ```json
  "rel.daysAgo_one": "Hace {count} día", "rel.daysAgo_other": "Hace {count} días"
  ```
* **No HTML** and no Markdown inside strings. Penny escapes everything.
* Keep it short — buttons and phone screens have little room.
* Quotes: use the typographic style of your language (« », “ ”). Keep the same meaning for the same key everywhere.
* Words that are brand or product names stay as they are: *Penny*, *Penny Pro*, *Windows*, *Mica*, *CSV*.
* The confirmation word for "Erase everything" is `erase.word`. The English word `ERASE` is always accepted too, so a keyboard layout can never lock someone out.

### Keys in groups

`nav.*` navigation · `common.*` shared buttons · `shell.*` top bar · `cmd.*` command palette · `tx.*` transaction form · `tf.*` transaction filters and bulk edit ·
`set.*` Settings · `backup.*` backup list · `upd.*` updates · `notif.*` notifications · `tray.*`/`jump.*` Windows tray and taskbar jump list ·
`err.*` start-up error screens · `rel.*` relative days · `freq.*` repeat frequencies · `widget.*`, `sound.*`, `lead.*` named options.

The tray menu and taskbar jump list are translated in the main process from the same files.

## Right-to-left (Arabic)

`<html dir="rtl">` is set from `meta.dir`; layout mirrors through CSS logical properties and a small `[dir="rtl"]` block at the end of `style.css`:
sidebar moves to the right, lists/dividers/search icon flip, directional icons (`chevron`, `chevleft`) mirror through the `.flip` class,
amounts/numbers/charts/keyboard hints keep left-to-right order, and the window-control corner stays where Windows puts it.
When writing new CSS prefer `margin-inline-start`, `padding-inline-end`, `inset-inline-start`, `text-align:start` over `left`/`right`.

## Numbers, dates, digits

* The *regional format* (Settings → Number & date format) is separate from the language: "Match language" by default, or any other region (e.g. English text with `de-DE` number format).
* Dates always use the **Gregorian** calendar, also for `ar-SA`, so they match the dates stored in the file.
* **Digits**: Western `0123456789` by default (safest for finance). For Arabic regions a "Digits" setting offers Arabic-Indic `٠١٢٣٤٥٦٧٨٩`. Typing Arabic-Indic digits into amount fields works; they are converted to plain numbers.

## For developers

```js
tr('tx.deleted')                         // plain text (toasts, notifications, attributes after esc())
tr('rel.daysAgo', { count: 3 })          // plural + variable
trh('tx.payee')                          // HTML-safe (message and variables escaped; text variables wrapped in <bdi>)
money(n)  dlong(d)  pct(x)  num(n)       // display formatting (core.js → Fmt)
```
Helpers are `tr`/`trh` (not `t`) because `t` is the loop variable for transactions throughout the code.
Never build a sentence by concatenating translated pieces — add a key with variables instead.
Never store a translated string in the data file.

Checks: `npm test` (unit tests incl. the locale checker), `npm run i18n:check`, `npm run test:e2e` (real Electron: language switch, persistence, RTL layout, data unchanged).
